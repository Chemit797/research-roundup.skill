# 文档骨架：逐节说明

目录：总览 · 题头 · 0 节 · 先说结论 · 一、信息列表（1.1–1.6）· 二、分工 · 三、交接 · 编号与引用约定

只放需要的表。资料少时参照 SKILL.md 的"精简版"。空白起点在 `assets/template.md`。

## 总览

| 部分 | 目的 | 读者读完能做什么 |
|---|---|---|
| 先说结论 | 5–12 条可单独转发的发现 | 决定要不要往下读；知道哪几件事要他拍板 |
| 一、信息列表 | 事实、核对、技术结论、资源表 | 判断每条信息能信到什么程度 |
| 二、分工 | 谁看什么、要回答什么、哪些事要定 | 领到自己的任务；知道优先级和截止 |
| 三、交接 | 总表新增行、未解决问题、证据位置 | 把结果接进总表；知道还欠什么 |

## 题头

```
# <主题或日期缩写>调研

本文是 <日期> 对 <被核对的材料> 的核实与分工，结构照 <上一轮文档>：信息列表 → 分工 → 交接。
日期为 <时区>；分数/数字一律注明 <权威口径> 或 <本地口径>；"名次/版本"指 <哪一次>。
```

一段话交代四件事：对象、结构、日期时区、数字口径。读者之后遇到任何数字，都能回到这里确认口径。

## 0. 这次核对了什么、怎么核的

两列表 `项 | 内容`，固定的行：

| 项 | 写什么 |
|---|---|
| 核对对象 | 被核对的材料有几份、各是什么；报告之后新出现的推送单列 |
| 仓库 / 来源 | 比对了多少个、哪些有变化；是否运行了代码（应为"没有"）；取回了哪些文件 |
| 权威数据（榜单、接口等） | 重拉了什么、什么时点；用什么核了什么 |
| 原文 | 读了哪些官方页面、文档、接口 |
| **没做到** | 没登录、没下载、没运行、读的是旧快照、只读了文字没复算……全写。这是全文最诚实的一行 |
| 证据与勘误 | 证据目录路径、证据清单在哪一节；与旧文档的出入是否已追加勘误 |

表后一行**计数行**："本文内容：逐条核对 N 行（其中 M 条做判定）、技术结论 N 条、页面与数据源 N 个、仓库 N 个；分工部分有 N 件待定的决定和 N 张指令卡；交接部分有……"。写完全文后用 `check_doc.py` 核对。

## 先说结论

blockquote，编号 5–12 条。每条：一个发现 → 为什么重要 → 指向正文（"§1.4 第 16 条"）。

- 每条自成一段，脱离上下文也读得懂（缩写第一次出现要展开）。
- 数字、名称、日期与正文逐字一致。
- 推荐顺序：①报告主干是否可信，要更正的几处（各给编号）；②最重要的新信息；③对我们的含义；④要先弄清的风险或规则；⑤看不到的；⑥要你们定的事（指向 §2.1）。
- 不确定的写"推断"，不要用"似乎""可能"含混带过。

## 一、信息列表

### 1.1 权威来源与规则：已核实的事实

表 `事项 | 内容 | 证据`。放不会因观点而变的事实：规则条款、截止时间、版本号、权威接口里的计数、官方公布的口径。每行证据列写文件路径或网址。

### 1.2 新动态

表 `对象 | 旧版本 → 新版本 | 时间 | 内容 | 对我们`。写明扫描的时间点（有几次扫描就写几次）；"报告之后才出现的"单独标出，因为报告没覆盖。"对我们"用 ★ / ○ / ✕。

### 1.3 报告逐条核对

按报告的章节分小节（1.3.1、1.3.2……），每小节一张表：

`# | 报告说法 | 核对结果 | 证据`

- "报告说法"用你的话概括，不抄原文；一个事实一行。
- "核对结果"以判定词开头，之后写依据、补充和更正后的说法。
- 表后写一段计数：共几行，几行不判定（建议 / 补充），属实几条、大体属实几条（列编号）、有误几条（列编号）、无法核实几条。

### 1.4 技术结论

按来源或主题分小节。每小节一张表：

`# | 结论 | 出处 | 证据强度 | 对我们`

- 编号全文通用（1–N），后面的分工用"§1.4 第 N 条"引用。
- 小节开头放一句背景（谁、什么时候、什么数据），并写明"本地"数字不是权威分。
- "对我们"必须可行动：用 / 不用 / 先验证什么 / 放到以后。
- 末尾放几张汇总表（差距表、分布表、相关对象对比表），每张注明数据来源和口径。

### 1.5 页面与数据源

表 `# | 页面 / 数据源 | 网址 | 本次核对`。"本次核对"写做了什么（打开了？读到了？只核了元数据？超时？），读不到的原样写读不到。

### 1.6 仓库列表

表 `仓库 | 文件是否包含数据 | 是否包含完整数据 | 最优表现 | 当前表现 | 方法（简述） | 本次变化 | 许可`。

- 只列本次有变化或被点名的；其余合并成一句"其余 N 个无变化"。
- 许可一列必须填；无许可写"无"，并在结论里提醒"只读不复制"。

## 二、分工

### 2.1 原则，和要你们定的事

- 原则：延续上一轮分工；按层或按主题分；★ 精读（有新东西、与目标直接相关）、○ 只看结论或变化、✕ 不用看；引用格式约定。
- 决定块 D1–Dn，优先级表。格式见 `assignment-handoff.md`。

### 2.2 / 2.3 每个人看的

每人一节，含：仓库与文件（编号，★/○，**要回答：**……）、页面、需要共同完成的表（例如"合规自查表"）、建议牵头的讨论方向。需要执行者跑的费力任务，在这里写成指令卡 K1–Kn。

### 2.4 都不用看的

表 `仓库 / 页面 | 理由`。把"已核清、不用再看"的列出来，省得每个人各自再核一遍。

### 2.5 时间

表（日期 × 人）。最终截止用绝对时间并注明时区，写明每天的提交额度或其他硬约束，建议留出的余量。

## 三、交接

### 3.1 看的重点

维度表 `维度 | 必须回答的问题`。每个仓库或资料按同一组维度看，保证不同人写出来的卡片可以合并。基础维度：定位、数据、方法、实验结果、评估方法、可复现性、对我们的价值；按项目加维度（例如"最终阶段适配""与我们协议的冲突""规则分类"）。

### 3.2 数据（资源）总表：本次新增的行

字段：`数据 | 出现位置 | 获取状态 | 背景 | 实验 / 对象 | 与目标的关系 | 许可 | 收录状态 | 证据 | 备注`。证据等级：A 文件或接口已核；B 清单或作者记录已读；C 只有作者文字或推测；D 二手转述。

### 3.3 评估方法总表：本次新增的行（及模板）

字段：`评估方法 | 来源 | 类型 | 输入 | 能否运行 | 与权威结果的对齐 | 可信等级 | 对我们的用途 | 风险`。可信等级：A 与多个权威结果基本一致（或实现就是权威函数）；B 单次对齐；C 只能做本地排序；D 未验证。需要的话在这里附"冻结卡"之类的模板。

### 3.4 两个人之间交接

沿用六项（见 `assignment-handoff.md`），再加"谁 → 谁、交什么、放哪里、何时"的表。

### 3.5 未解决问题

编号列表；每条写清缺什么、谁来了结、怎么了结。再放一张"上一轮遗留问题的进展"表：`上一轮第 N 条 | 状态`，状态只用：已解决 / 部分 / 未进展 / 本次未涉及。

### 3.6 机器证据

表 `文件 | 内容`，列证据目录里每个文件或每组文件。脚本一栏注明"只读，不执行仓库代码"。

## 编号与引用约定

- 每张表的第一列 `#`；同一节内编号连续，不同节之间若要全文通用就接着编（如 §1.4 的 1–28 跨好几张表）。
- 引用写"§1.3 第 8 条""§1.4 第 16 条""§2.1 D1""§2.3 K4"，一律带节号。
- 对别的文档的引用带文档名或日期（"3/10 调研 §1.7""3/02 方案 06 号文档 §4.1"），不要只写"06 号文档"，当天文件夹里可能有同号的另一份。
- 分数、比例旁边注明口径；两个口径并列时分行写。
