# 交付前自查

先跑 `python scripts/check_doc.py 文档.md --root 证据目录`，再逐项过下面的清单。每项都是"为什么要查"加"怎么查"。

## 数字与口径

- [ ] 开头的计数行与各表的行数、判定统计一致。（读者会拿它当目录；`check_doc.py` 会打印行数和判定计数）
- [ ] 每个比例、差值、计数、排名都有口径（阈值、去重、时间点、原始值还是缩放值），并且能追到一个结果文件。
- [ ] 写了"可复算"的，脚本和输出都在证据目录里。
- [ ] 两个口径不同的数没有被并排比较；确实并列时，口径分行写明。
- [ ] 每个分数标了"权威"还是"本地"；本地分没有被换算成权威分。

## 判定与证据

- [ ] 核对表每行以判定词开头；建议和补充行标了"不判定"。
- [ ] 技术结论每条有出处和证据强度；"推断"没有伪装成"原文"。
- [ ] 没有"提升""有效""因果"的说法缺少对照证据；缺证据的写"未验证"。
- [ ] 靠名字对上的身份写了"未确认"；没有对个人或团队下认定。
- [ ] 规则、许可、合规类内容：条款原文在证据文件里，正文转述，给了分类框架，写明不是法律意见，没有替人下结论。

## 引用与结构

- [ ] §引用都能在文档里找到对应标题；对别的文档的引用带文档名或日期。
- [ ] 编号连续、全文通用；没有重排旧编号。
- [ ] 证据路径存在（`--root` 检查）；仓库内路径按需要忽略。
- [ ] 没有占位符（`@@`、TODO、【填】）。
- [ ] 正文没有长段原文；逐字摘录都在证据文件里。

## 分工与交接

- [ ] 每个清单项有"要回答："，问题可验收，不超过三个。
- [ ] 每个决定块有推荐默认、依据、谁和何时、不照默认的代价。
- [ ] 优先级表按"冻结点前能不能改变一个决定"排序；别处已列的事项注明了。
- [ ] 每张指令卡有输入、做、输出、不做、成本；通用要求写在卡片前。
- [ ] 时间表用绝对日期和时区；最终截止留了余量。
- [ ] 交接六项都有内容；未解决问题每条有负责人或"无人认领"；上一轮遗留问题有进展。

## 边界与安全

- [ ] "没做到"如实列出：没登录、没下载、没运行、读的是旧快照、没复算。
- [ ] 没有运行陌生代码，没有下载大文件或权重。
- [ ] 文档和证据目录里没有密码、token、私钥、个人隐私。
- [ ] 无许可证的仓库标了"只读不复制"，且没有复制它的代码或表格。
- [ ] 内部路径、人名是否能外传，问过一句。

## 登记

- [ ] 文件编号取的是当天文件夹的下一个空号（写入前又查了一次）。
- [ ] 项目索引（README 或总目录）追加了一行；旧文档的出入已追加勘误，没有改旧文。
- [ ] 回复里说清了：文档在哪、哪些没做到、需要用户拍板的是哪几件。
